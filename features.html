What the BROWN POS can do

Every function in the system, by screen. Built from the pages and server modules of the BROWN POS (Vue 3 web app, NestJS API, PostgreSQL). For how it is designed and hosted, and every database table, see the System guide.

in use used and tested with real store data ready built and working, not yet used with real data

1Cashier screen

What the cashier uses all day, at /pos. Works on a PC, a tablet or a touch screen.

Shift and sign-in in use

  • Each cashier logs in and sees only their own store(s)
  • Open a shift with the opening cash; close it with a cash count
  • X report: the shift so far, any time
  • Cash in / out during the shift (manager PIN when the store requires it)

Finding products in use

  • Search by name or SKU, or scan a barcode
  • Type 3*8850000001 to add 3 at once
  • Group buttons (Beverages, Food…) with their categories in a second row
  • Product tiles with photos, coloured by category
  • On-screen keyboard and Big mode for touch screens

Drink options and sizes in use

  • Size S / M / L with each store's own prices from BROWN
  • Sugar, ice, milk, coffee level, and add-ons with prices
  • Each drink offers only its own options
  • Required options must be chosen before adding

The order in use

  • Change quantity, edit a line, add a note
  • Discount (cashiers are limited to the store's maximum)
  • Hold an order and Recall it later
  • Takeaway or Dine-in
  • Promotions apply by themselves: % off, amount off, buy X get Y, by day and time

Payment in use

  • Cash in USD or riel (at the store's rate), with change
  • Card, KHQR (QR to scan), bank transfer, e-wallet
  • The store's own Wallet card, gift vouchers, coupons
  • Split one sale over several payments

Receipt and customer in use

  • Print on an 80 mm receipt printer, in English or Khmer
  • Member (F4): add a customer to the sale, or register a new member
  • Top up a wallet card
  • Customer display: a second screen shows the order, total and promotions

Works offline ready

  • Products and prices are kept on the device
  • Sales made without internet are saved and sent when it comes back
  • Only changed products are downloaded on each update

Shortcuts

  • F2 search · F4 member · F9 pay
  • Enter new sale after payment

Order board /board

For customers, on their own phone.

Order online /order/B001

Member app /m

4Admin portal

For managers and head office. Super admins see every store; store managers see their own. Pop-ups open as a panel on the right; click outside to close.

Overview in use

  • Dashboard: today's and recent sales
  • Reports: sales by store, cashier and channel; products sold; payments by method; refunds; discounts; promotions and coupons used; top customers; points; bakery production and waste; profit and margin; CSV export

Selling in use

  • Sales: every receipt in a side panel; print, refund (part or all) and void, with manager approval when required
  • Shifts: expected vs counted cash
  • End of day (Z report) per store and day
  • Customers: find, add, edit, adjust points
  • Wallet cards: generate (CSV), activate, top up, block, replace a lost card, history

Catalogue in use

  • Products: one list for all stores, photo, category colour, price, margin and stock badges, "sold in this store" switch, Khmer name, tax
  • Size prices: S / M / L boxes under Selling price for the chosen store
  • Categories: groups with their categories (Beverages › Hot Drinks)
  • Drink options: option groups with prices and defaults
  • Ingredients with cost per unit or from a pack price

Stock and production ready

  • Recipes: ingredients per product; selling uses them up
  • Bakery production: bake a batch (uses ingredients, adds pieces), freshness hours, waste
  • Inventory: stock per store, adjust stock, reorder levels
  • Transfers between stores
  • Suppliers and purchase orders, then receive goods into stock

Marketing in use

  • Promotions: automatic deals by product, category or group, store, dates, days and hours
  • Coupons: one shared code or many unique codes (CSV), minimum spend, maximum discount, usage limits, members only
  • Gift vouchers: batches of codes, used as a payment

Administration in use

  • Users: super admin, store manager, cashier, with store access per user; managers set an approval PIN
  • Stores: tax, currency, riel rate, KHQR, café, online ordering, approval rules (refund, void, cash-out, cashier discount)
  • Audit log: who changed what and when (prices, refunds, syncs…), never secrets
  • Integrations: API keys and webhooks for other systems
  • System monitor: server health and Telegram alerts

5BROWN menu sync in use

Brings the menu from the BROWN system into the POS, per store.

What is synced

  • BROWN groups become parent categories, with their categories under them
  • Items are matched by SKU (BROWN item id): new ones are created, existing ones updated
  • Sizes from the item detail (S, M, L) with this store's prices
  • Each drink's own options and priced add-ons

How to run it

  • Sync on one store, or Sync all stores with a progress list
  • A run stops early if every store gets the same error (for example an expired token)
  • Paste a response when the server cannot reach BROWN
  • A clear message when it fails, and the reason in the server log

6Server and hosting

See Hosting and How the server works in the System guide for the details.

Running

  • Docker Compose on a cloud server: web app, API, PostgreSQL, Redis
  • Public link through a Cloudflare tunnel
  • Database backed up automatically

Safety

  • Passwords and PINs stored as hashes
  • Logins limited to 10 tries a minute
  • Each request is logged; tokens never are
